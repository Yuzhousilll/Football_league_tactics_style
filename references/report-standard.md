# 报告交付规范

默认交付 HTML（图表内嵌、可独立打开）和 Markdown（图表为相对路径），附清洗数据、载荷、得分、聚类中心、趋势、参数和校验清单。报告标题使用项目名，副标题注明本次联赛、实际赛季范围和样本数。章节按论文最终版六章，最后附来源、方法限制和可复现文件说明。

- 图表按章节编号，表格需有明确字段、单位及缺失符号。日期、比赛场次、球员每90分钟口径统一。报告中的公式若新增，HTML采用MathML/渲染图，Word采用原生公式，Markdown使用可渲染数学格式，不将未渲染源码作为成品。
- 正文描述本次数据，结论引用实际数值；给出变化的起止赛季。每个因子的命名以实际载荷为依据，聚类只在本次拟合内解释。
- 指定球队/球员未出现时失败并提示名称或覆盖问题；部分赛季不存在时逐项列出，不自动当作零。
- 只有排行榜数据时明确榜单筛选偏差，不把前十均值称作全联赛均值。球员角色与空间效应需要更多直接证据；可说明当前数据支持的产出与结构关系，不编造战术细节。
- 没有模型的章节仍保留并写明原因，允许只产出描述报告；交付时说明模型是否可用。模型适配性检验不是因果识别或外部预测能力的证明。
- 输出目录通过临时目录整体完成，成功后才发布到目标目录；失败清理本次临时文件。既有报告不覆盖。
- `manifest.json` 保存输入和输出SHA256、版本、运行时间；不包含密钥。版本和时间等元数据会使不同运行文件哈希改变，数值复现应比较数据与模型结果。

交付前检查样本数、数据口径、真实积分、缺失、图表编号、HTML表格可读性及链接。要制作Word/PDF时以本次报告为内容源，参考论文的章节和学术风格，保留适当页边距、表头重复与图注；最终渲染检查，不携带原论文封面个人信息。
